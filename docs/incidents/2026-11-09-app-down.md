Container `app` bị dừng có chủ đích để diễn tập.

Khi backend không hoạt động, Nginx không thể kết nối đến dịch vụ ứng dụng tại `app:8000`, dẫn đến lỗi HTTP 502.

## Cách xử lý

- Kiểm tra trạng thái container bằng `docker compose ps`.
- Xác nhận container app đã dừng.
- Kiểm tra endpoint bằng `curl -I http://localhost/health`, ghi nhận HTTP 502.
- Khởi động lại ứng dụng bằng:

```bash
docker compose start app
```

- Kiểm tra lại trạng thái container.
- Chạy `curl http://localhost/health`, nhận kết quả `{"status":"ok"}`.

## Bài học và việc cần làm

- Khi app dừng, Nginx có thể trả HTTP 502 dù bản thân Nginx vẫn hoạt động.
- Cần kiểm tra trạng thái container và log Nginx để xác định lỗi nằm ở backend.
- Health Check HTTP 200 sau khi khởi động lại là bằng chứng quan trọng để xác nhận phục hồi.
- Lần sau cần ghi `date` trước và sau mỗi thao tác để tính chính xác thời gian gián đoạn.
